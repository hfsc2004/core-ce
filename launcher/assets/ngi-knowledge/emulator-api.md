# External emulator API and returned values
The existing kT-emulator runs separately and owns its emulator Core. Relay connects over HTTP; it does not create another Core. The inspected frontend has one lane and activation address (0,).
Read State uses GET /api/state to read a snapshot. Evaluate uses POST /api/evaluate with instruction and noise, executes one instruction, and increments step. Reset uses POST /api/reset with seed, model, init, read_noise, and optional start_y, rebuilding the emulator state. These operations are manual controls, not helper draft tools.
Snapshots include y (activation), ga and gb (conductances), magnitude (ga + gb), step, instruction, model, init, seed, and read_noise. A differential lane uses relative conductance to represent a signed response. An evaluation's y and conductance snapshot can describe different points within the instruction; do not assert that every value changes after every instruction.
Evaluation noise 0 does not automatically set the separately configured read_noise to zero. Compare recorded values and explicit settings rather than assuming a deterministic run. Current integration has no cycle, sample, preset, Monitor API, multi-lane, or automatic execution support.
