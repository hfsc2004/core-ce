# Observation, numeric mapping, and drive
Observation describes a model-state measurement. BMOC owns the RWKV7 native recurrent sequence and its lifetime. Turn counts, token counts, and message counts describe activity; they do not measure recurrent tensor contents. The registered rwkv7-native-sequence observation is projected inside BMOC using seeded-rademacher version 1. Relay receives scalar q, successive-q delta, seed/version, element count, and status, never native tensors.
Numeric mapping transforms an observation, or a change between observations, into a numeric signal suitable for the single kT neural lane. The registered scaled-delta-sign mapping multiplies the successive-q delta by the configured finite scale and selects its sign. A mapping is not an instruction or a noise parameter. Only registered IDs/versions accepted by live validation are executable. The first completed turn establishes a baseline with no delta or emulator instruction; reset/restart/generation changes invalidate it.
Drive specifies mode, instructions, and evaluation noise. single-instruction sends only the chosen instruction. read-feedback executes FF first with configured noise, records fresh y, then executes the selected positive/negative instruction with noise 0 and records post-feedback ga, gb, and magnitude. Read and feedback have separate trace steps. A failed read prevents feedback; partial execution is not retried. For example FF with noise 0 configures drive independently of mapping. It does not define how RWKV state becomes a signal. Trigger specifies when a future measurement would run; logging specifies what records to retain.
Observation-only means emulator output never enters RWKV inputs. The helper manages proposals; it does not participate in the measurement loop. No loop, feedback, snapshots, or cloning is implemented.
