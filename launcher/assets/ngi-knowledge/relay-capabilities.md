# Relay permissions and experiment capabilities
The Experiment Assistant is a separate model-backed Agent with deployed NGI management permission. The persistent RWKV7 subject has that permission disabled and is assigned to the external kT-emulator Gateway. Backend-owned requesting identity is authoritative; model-provided identities cannot grant permission.
Private helper chat supports inspection, source proposals, mapping declarations, drive proposals, trigger/logging proposals, validation, status, and results. Full Pipeline cannot dispatch IRG tools. General explanations require no tool; checking the current draft requires the validation tool. Validation reports all missing fields and capability blockers without changing draft revision.
Current capability lists and validation from the backend override this documentation. Compatible persistent RWKV7 sessions support rwkv7-native-sequence, seeded-rademacher version 1, successive-q version 1, and scaled-delta-sign version 1. Validation requires an available compatible native reader, a complete definition, explicitly chosen positive/negative instructions, and after-persistent-turn trigger. Explicit user UI/CLI Apply freezes the validated revision, Arm checks the emulator and native reader, Start enables completed-subject-turn observations, and Stop drains execution and releases the observation baseline. Helper output cannot authorize any Apply/Arm/Start/Stop transition. The measurement loop contains no helper calls and no emulator feedback into RWKV.
UI, CLI, and IRG use one shared draft revision. Portable manifests contain the definition, excluding local Agent/session/endpoint details; validation/results carry runtime provenance separately. Draft edits never execute/reset the emulator or model. Manual Gateway controls remain explicit user operations. Saved definitions survive redeployment; conversations, revisions, applied status, and validation provenance start a new lifetime.
